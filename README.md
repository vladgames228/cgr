# cgr

Бот сравнивает тексты с единым индексом всех добавленных каналов. Индексация и публикация новых постов работают независимо. Бот пишет администратору только в ответ на команду.

## Запуск

1. Заполни `.env` по `.env.example`.
2. Для первой авторизации пользовательского аккаунта: `docker compose run --rm --build cgr login`.
3. Запусти `docker compose up -d --build --remove-orphans`.
4. Напиши боту `/channel @источник @мой_канал`. История начнёт индексироваться, публикация останется выключенной. Аккаунту из `login` нужны права публикации в канале назначения.

При переходе со старой версии останови контейнер и очисти старый `archive.sqlite3`: новая база сознательно не подхватывает прежние очереди и настройки. Telegram-сессии и модель можно сохранить. При переименовании сервиса с `bot` на `cgr` используй `docker compose down --remove-orphans` **без `-v`**, затем запусти новую версию: том `data` останется.

## Команды в личке

| Команда | Действие |
|---|---|
| `/status` | Режимы, размер базы, новая работа, очередь и последняя ошибка. |
| `/channel @источник @мой_канал` | Добавить источник и канал назначения; новый канал пополняет общий индекс. Если публикация уже включена хотя бы у одного канала, новый тоже начнёт публиковать только будущие посты. `/channel` показывает список. |
| `/channel remove @источник` | Убрать источник из наблюдения. Уже индексированные посты остаются в общей базе. |
| `/group add @группа ID_автора` | Следить за новыми сообщениями автора в группе, доступной аккаунту из `login`. Группу можно указать также ID вида `-100...`. |
| `/group` | Список групп; `/group recent ID` — последние оценки; `/group off ID`, `/group on ID`, `/group remove ID` — управление. |
| `/minwords N` | Минимум слов в новых сообщениях для индексации; по умолчанию 3. Старые записи не удаляются. |
| `/post on @источник` или `/post off @источник` | Включить или выключить публикацию **новых** постов одного источника. Без источника команда действует на все каналы. |
| `/index on @источник`, `/index off @источник`, `/index rebuild @источник` | Управлять индексацией одного источника. Без источника `on/off` действуют на все; `rebuild` при нескольких каналах требует указать источник. |
| `/llm on` или `/llm off` | Включить или выключить MiniLM. При первом включении модель скачивается в том `data`. |
| Текст, ссылка или пересланный пост | Просто отправь боту в личку: он сразу проверит и ответит. |
| `/reverse on` или `/reverse off` | Поменять направление: 100% означает повтор или новый текст. |
| `/label текст` или `/label reset` | Изменить или сбросить подпись перед процентом. |
| `/stat` | Частые основы слов и выражения с числом постов, где они встречались. |
| `/queue` | Показать очередь. `clear`, `pause`, `resume` — очистить, остановить или продолжить её. |
| `/stop` | Остановить публикацию, индексацию и очередь. |

Бот и ответ в канале показывают одну цифру — уникальность относительно общего индекса всех добавленных каналов. Одинаковые тексты в разных каналах учитываются в статистике один раз. Четыре самых привычных слова текста имеют повышенный вес, но новые слова тоже учитываются. Частота считается по числу разных постов, где встречалось слово; при частоте около 2% оно считается привычным. Повторённые выражения и, при включённой MiniLM, близкие по смыслу фрагменты могут дополнительно снизить итог. Это оценка повторения в корпусе, а не вероятность авторства нейросети. Ссылка на пост сравнивается со всей базой, кроме самого поста. Только в личке бот покажет ссылку на похожий пост, если совпадение слов и выражений выше 60%. Под результатом в личке есть кнопки «Индексировать» и «Запостить»; в канале остаётся одна строка.

`/stat` показывает то, что реально посчитано из текстов: частоту основ слов и выражений. MiniLM хранит векторы для сравнения фрагментов, но не размечает посты по названиям тем, поэтому частоты тем в `/stat` нет. `/reverse` и `/label` сохраняются между перезапусками и влияют на новые оценки; уже ожидающие в очереди ответы не меняются.

После обновления алгоритма включи `/llm on`: бот постепенно добавит векторы MiniLM к уже сохранённым записям. Базу удалять не нужно. Пока векторы ещё строятся, оценка использует слова и выражения; прогресс виден в `/status`. `/index rebuild` остаётся способом вручную пересобрать историю с начала. Не удаляй том Compose: в нём находятся настройки, Telegram-сессия и скачанная модель.

Когда `/post on`, пользовательская сессия копирует новый пост в канал назначения. Затем она публикует там оценку с цитатой исходного текста через функцию ответа Telegram. Для длинных постов Telegram ограничивает длину цитаты. В группу обсуждений бот ничего не отправляет. `/post off` не трогает `/index`; `/index off` не трогает `/post`. Ожидающие публикации видны через `/queue`; `/queue clear` удаляет их из очереди.

Группы читаются пользовательской сессией раз в `POLL_SECONDS` секунд (по умолчанию 30). При добавлении группы обработка начинается с новых сообщений. Оценки не присылаются на каждое сообщение: последние доступны через `/group recent ID`. Повтор текста в одной базе оценивается, но не индексируется второй раз. `/stat` не показывает короткие служебные слова и фразы с ними.

Если бот или пользовательская сессия получает событие нового поста источника, его текст сразу сохраняется, даже если пост удалят до следующего обхода истории. Ссылку на такой пост можно проверить по сохранённому тексту; кнопка «Запостить» опубликует текст, если исходный пост уже удалён. Медиа не архивируется. Обход истории остаётся на случай перезапуска и пропущенных событий. Пост, удалённый до получения события и до обхода истории, Telegram уже не отдаст.

База, сессии и модель хранятся в томе Compose `data`. Локальные тесты: `python -m unittest discover -s tests -v` после установки зависимостей из `requirements.txt`.
