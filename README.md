# Накопительный анализ постов Telegram

Приложение читает публичные каналы через пользовательскую MTProto-сессию, анализирует их по отдельности и публикует четыре оценки комментарием к посту в канале назначения.

## Установка и обновление

1. Скопируй `.env.example` в `.env` при первой установке. Если `.env` уже есть, добавь только `TG_ADMIN_IDS` и сохрани текущие значения. Список принимает числовые ID пользователей через запятую. Это ID аккаунтов, которые управляют ботом в личке. Команда `login` выводит ID аккаунта, которым ты вошёл.
2. У канала назначения должна быть привязана группа обсуждений. Пользовательский аккаунт должен состоять в группе и иметь право публикации в канале. Добавь бота в группу с правом отправлять текст. Для нового назначения эти права выдаются в Telegram.
3. При первом запуске, если сессии ещё нет, выполни:

   ```bash
   docker compose run --rm --build bot login
   ```

   Введи номер, код Telegram и пароль 2FA, если настроен. Авторизованный аккаунт может отличаться от владельца приложения и создателя бота.

4. Запусти или обнови приложение:

   ```bash
   docker compose up -d --build
   ```

   При сборке Compose скачает MiniLM и проверит контрольные суммы. Дополнительные файлы Compose и ручное скачивание весов не нужны. При обновлении используй прежнее имя проекта Compose и прежний том, чтобы сохранить сессии, SQLite и очередь.

5. В личке бота отправь `/route @источник @назначение` для каждого источника. Старые маршруты из `channels.json` нужно задать в личке один раз. Если источник и назначение прежние, бот продолжит с сохранённого курсора. При активации такого маршрута старая очередь постов, пропущенных из-за защиты пересылки, будет поставлена на отправку копиями. Сохранённые оценки используются повторно.

## Команды в личке

| Команда | Действие |
|---|---|
| `/route @source @destination` | Добавить, возобновить или сменить маршрут. |
| `/status` | Режим, каналы, прогресс, очередь и число пропусков. |
| `/pause @source` | Остановить чтение и отправку по маршруту. |
| `/drain @source` | Остановить чтение и доставить текущую очередь. |
| `/mode minilm` | Включить локальную CPU-модель. Это режим по умолчанию. |
| `/mode classic` | Выключить модель и использовать классический анализ. |
| `/help` | Показать команды. |

Для источника подходят публичная ссылка или `@username`. Для приватного назначения укажи ID `-100…`. Например, ссылка на пост `https://t.me/c/1234567890/42` соответствует ID канала `-1001234567890`.

Чтобы сменить назначение с сохранением очереди, выполни `/drain @source`, дождись нуля в `/status` и заново укажи `/route`. Если старое назначение недоступно и остаток очереди можно пропустить, используй `/route @source @new_destination skip_pending`. База анализа и уже опубликованные посты сохранятся. Настройки маршрутов и режима сохраняются между перезапусками. Посторонние и команды в группах игнорируются.

## Анализ и отправка

- Формулировки сравниваются по словам, словосочетаниям и последовательностям символов. Тематика — по лексике. Смысл — по совпадению словарных понятий и, в режиме MiniLM, по эмбеддингам. Стиль — по структуре предложений, пунктуации, словарному разнообразию и другим измеримым признакам.
- Первая публикация каждого источника получает 100% по всем четырём показателям. Следующие сравниваются с предыдущими публикациями и отдельными фрагментами. Поиск кандидатов приближённый. При включении MiniLM бот добавляет недостающие эмбеддинги истории по мере обработки. Старые оценки и отчёты сохраняются.
- Бот сначала пробует штатную пересылку. Если Telegram её запрещает, пользовательская сессия публикует новую копию текста и форматирования с доступными вложениями. Фото, видео, документы и доступные части фото- и видеоальбомов копируются с подписями. Бот отвечает четырьмя строками под опубликованным сообщением. Закрытые для скачивания вложения, платное и исчезающее медиа, интерактивные элементы и специальные типы Telegram могут быть недоступны для воспроизведения. Посты без текста учитываются при копировании частей альбома, но отдельно не анализируются.
- Прогресс и ID отправок сохраняются в SQLite. Для живых постов период проверки задаётся `POLL_SECONDS` в `.env`. Compose ограничивает сервис двумя CPU и 2 ГБ ОЗУ. Для больших медиа нужен свободный диск на хосте. Модель работает на CPU, а в режиме `classic` её файлы остаются в образе.
- SQLite, сессии и настройки хранятся в томе Compose `data`. При отзыве пользовательской сессии Telegram потребуется повторный `login`. Для диагностики используй `docker compose logs -f bot` и `docker compose run --rm bot status`.

## Локальные проверки

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Для проверки реальной модели установи зависимости из `requirements-semantic.txt` и задай `TEST_MODEL_DIR` с путём к `model.onnx` и `tokenizer.json`. Для локального замера используй `PYTHONPATH=. python tests/benchmark.py --posts 1500`.
