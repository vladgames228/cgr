# Накопительный анализ постов Telegram

Приложение читает историю публичных каналов через пользовательскую MTProto-сессию. Сессия пересылает публикации в указанный канал, а бот публикует отчёт комментарием к пересланному посту. Каждый источник получает собственную историю сравнения в SQLite.

## Запуск

1. Получите `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org/) и токен бота у [@BotFather](https://t.me/BotFather). Заполните файлы:

   ```bash
   cp .env.example .env
   chmod 600 .env
   cp channels.example.json channels.json
   ```

   В `channels.json` укажите по одной записи на источник. Для источника подходят `https://t.me/имя` и `@имя`. Для назначения подходит публичная ссылка или числовой ID приватного канала. Например, ссылка на пост `https://t.me/c/1234567890/42` соответствует ID канала `-1001234567890`. Назначение может быть общим для нескольких источников.

2. В настройках канала назначения привяжите группу обсуждений. Пользовательской сессии нужны право публикации в канале и членство в группе. Добавьте бота в эту группу с правом отправлять текстовые сообщения. Добавлять кого-либо в исходный канал не требуется. [Как Telegram связывает посты и комментарии](https://core.telegram.org/api/discussion)

3. Соберите контейнер, авторизуйте пользовательскую сессию, проверьте настройки и запустите сервис. Telegram запросит номер телефона, код подтверждения и пароль двухэтапной аутентификации, если он настроен.

   ```bash
   docker compose build
   docker compose run --rm bot login
   docker compose run --rm bot check
   docker compose up -d
   ```

   Команда `check` проверяет сессии и маршруты без отправки сообщений. Отправка начнётся после `up`. Для первой проверки можно указать отдельный канал назначения без аудитории.

   ```bash
   docker compose logs -f bot
   docker compose run --rm bot status
   ```

   Поле `history_done` показывает завершение первичной индексации, `indexed` — число проанализированных публикаций, `delivered` — число опубликованных отчётов, `pending` — очередь, `skipped` — случаи, когда отправка невозможна. Причина пропуска записывается в журнал и SQLite.

## Как считаются оценки

| Показатель | Признаки |
|---|---|
| Формулировки | Совпадения слов, пар и троек слов, последовательностей из пяти символов и нормализованных фрагментов. |
| Тематика | Сходство частот слов после удаления служебных слов и стемминга русского и английского текста. |
| Смысл | Сходство словарных понятий и их последовательностей с поправками на отрицания и числа. Дополнительный режим учитывает сходство эмбеддингов. |
| Стиль | Длина предложений и слов, разнообразие лексики, доли служебных слов, первого лица и эмоциональных маркеров, пунктуация, переносы, регистр и эмодзи. |

Для каждого показателя берётся наиболее сильное совпадение с предыдущими публикациями, найденными поисковым индексом. Повторение отдельного предложения или окна внутри длинного текста снижает оценку с поправкой на длину фрагмента. Предыдущие публикации ищутся по индексированным ключам в SQLite. Списки кандидатов имеют фиксированные лимиты, поэтому поиск приближённый и может пропускать совпадения. Классический режим хорошо видит прямые повторы и знакомые синонимы. Для глубоких перефразировок с другой лексикой включите режим ниже. Оценки стиля особенно чувствительны к коротким текстам.

Первый текст каждого канала получает четыре оценки по 100%. В отчёте публикуются ровно четыре строки с целыми процентами.

## Дополнительный CPU-режим для анализа смысла

Выберите режим **до первого запуска `check` или `run` с новой базой**. Используется квантованный энкодер MiniLM для AVX2 объёмом около 118 МБ. После скачивания файлы читаются локально. Лимиты Compose остаются 2 vCPU и 2 ГБ ОЗУ.

```bash
mkdir -p model
model_url=https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/resolve/e8f8c211226b894fcb81acc59f3b34ba3efd5f42
curl -fL "$model_url/onnx/model_quint8_avx2.onnx" -o model/model.onnx
curl -fL "$model_url/tokenizer.json" -o model/tokenizer.json
sha256sum -c <<'CHECKSUMS'
98a01d88b7de996cdea58c32ca71208c09968d143798814b2ea09d3439dc334f  model/model.onnx
2c3387be76557bd40970cec13153b3bbf80407865484b209e655e5e4729076b8  model/tokenizer.json
CHECKSUMS
```

В командах запуска используйте оба файла Compose:

```bash
docker compose -f compose.yaml -f compose.semantic.yaml build
docker compose -f compose.yaml -f compose.semantic.yaml run --rm bot login
docker compose -f compose.yaml -f compose.semantic.yaml run --rm bot check
docker compose -f compose.yaml -f compose.semantic.yaml up -d
```

В базе закрепляется выбранный набор признаков, включая хеш файлов модели. Для осознанной повторной обработки используйте новый проект Compose с новым томом и каналом назначения. SQLite и сессии из старого тома сохранятся. [Карточка модели и файлы ONNX](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/tree/main/onnx)

## Порядок чтения и отправки

- История читается небольшими страницами от старых публикаций к новым. Снимок верхней границы и курсор сохраняются. После первой индексации новые посты проверяются каждые `POLL_SECONDS` секунд. Правки уже обработанных постов не запускают пересчёт.
- Подпись к медиа обрабатывается как обычный текст. В альбоме обрабатываются сообщения с подписью. Части альбома без текста пропускаются. Telegram может запрещать пересылку отдельных постов или всего источника. Такие тексты остаются в базе, а их доставку приложение отмечает как пропущенную.
- Очередь публикации хранится в SQLite. Пересылка и комментарий получают собственные постоянные `random_id` MTProto. При сетевом сбое запрос повторяется с тем же ID; Telegram использует его для дедупликации. Успешные этапы сохраняются отдельно. [Дедупликация отправки в MTProto](https://core.telegram.org/api/updates)
- Комментарии отправляются с интервалом от 3,1 секунды в одну группу. На доставку 1 000 постов в одну группу уйдёт минимум около 52 минут. Дополнительные паузы определяются ответами Telegram. Индексация продолжает работать при сбоях отправки и возобновляется при восстановлении доступа к источнику.
- База и сессии лежат в томе Compose `data`. Для согласованной резервной копии остановите сервис и скопируйте том целиком. Храните копию и `.env` как учётные данные. `restart: unless-stopped` восстанавливает работу при запуске Docker, если контейнер не был остановлен вручную.

## Проверки и замеры

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
PYTHONPATH=. python tests/benchmark.py --posts 1500
```

При установленных зависимостях из `requirements-semantic.txt` и скачанных весах установите `TEST_MODEL_DIR=./model` для проверки реального энкодера. Тот же бенчмарк для модели запускается с `--posts 150 --model-dir ./model`. Для сопоставимого замера задайте `TOKENIZERS_PARALLELISM=false`, `OMP_NUM_THREADS=1` и `OPENBLAS_NUM_THREADS=1`.

На синтетических коротких постах с привязкой к двум CPU в тестовой среде AMD EPYC классический режим обработал 1 500 постов примерно за 21 секунду при пике 36 МиБ RSS. Режим с энкодером обработал 150 постов примерно за 17 секунд при пике 561 МиБ RSS. Замеры включали SQLite и обработку текстов. Скорость доставки в Telegram и работа на целевом Xeon в эти замеры не входили. Тесты транспорта проверяют MTProto-запросы и восстановление на имитации ответов. Для проверки на реальных каналах нужны настройки и сессии пользователя.
