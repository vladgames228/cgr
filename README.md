# cgr

Бот сравнивает тексты с проиндексированной историей исходного канала. Индексация и публикация новых постов работают независимо. Бот пишет администратору только в ответ на команду.

## Запуск

1. Заполни `.env` по `.env.example`.
2. Для первой авторизации пользовательского аккаунта: `docker compose run --rm --build cgr login`.
3. Запусти `docker compose up -d --build --remove-orphans`.
4. Напиши боту `/channel @источник @мой_канал`. История начнёт индексироваться, публикация останется выключенной. Аккаунту из `login` нужны права публикации в канале назначения.

При переходе со старой версии останови контейнер и очисти старый `archive.sqlite3`: новая база сознательно не подхватывает прежние очереди и настройки. Telegram-сессии и модель можно сохранить. При переименовании сервиса с `bot` на `cgr` используй `docker compose down --remove-orphans` **без `-v`**, затем запусти новую версию: том `data` останется.

## Команды в личке

| Команда | Действие |
|---|---|
| `/status` | Режимы, размер базы, новая работа, очередь и последняя ошибка. |
| `/channel @источник @мой_канал` | Выбрать источник и канал назначения. |
| `/post on` или `/post off` | Включить или выключить публикацию **новых** постов. При включении старые посты не отправляются. |
| `/index on`, `/index off`, `/index rebuild` | Включить, выключить или пересобрать базу с начала. Пересборка не удаляет настройки и Telegram-сессию. |
| `/llm on` или `/llm off` | Включить или выключить MiniLM. При первом включении модель скачивается в том `data`. |
| `/an` | Следующим сообщением пришли ссылку, перешли пост или вставь текст. Ответ придёт в личку. Можно также написать `/an ссылка` или `/an текст`. |
| `/queue` | Показать очередь. `clear`, `pause`, `resume` — очистить, остановить или продолжить её. |
| `/stop` | Остановить публикацию, индексацию и очередь. |

`/an` показывает общую новизну, новизну словаря и выражений относительно **всех** текстовых постов источника. Слово считается привычным, если встречается хотя бы в 2% постов; выражение — если уже встречалось. При включённой MiniLM добавляется новизна темы: доля фрагментов без близкого фрагмента в истории (порог близости 0,82). Общая новизна равна самому низкому из доступных показателей. Это показатели повторения внутри канала, а не вероятность авторства нейросети. Ссылка на пост сравнивается со всей базой, кроме самого поста. Под результатом есть кнопки «Индексировать» и «Запостить».

После обновления алгоритма включи `/llm on`: бот постепенно добавит векторы MiniLM к уже сохранённым записям. Базу удалять не нужно. Пока векторы ещё строятся, показатель темы сообщит, что индекс не готов. `/index rebuild` остаётся способом вручную пересобрать историю с начала. Не удаляй том Compose: в нём находятся настройки, Telegram-сессия и скачанная модель.

Когда `/post on`, пользовательская сессия копирует новый пост в канал назначения. Затем она публикует там **новый пост с оценкой как ответ на копию**. В группу обсуждений бот ничего не отправляет. `/post off` не трогает `/index`; `/index off` не трогает `/post`. Ожидающие публикации видны через `/queue`; `/queue clear` удаляет их из очереди.

База, сессии и модель хранятся в томе Compose `data`. Локальные тесты: `python -m unittest discover -s tests -v` после установки зависимостей из `requirements.txt`.
