# Анализ уникальности Telegram каналов

Бот собирает историю каждого исходного канала в отдельную базу, сравнивает тексты по формулировкам, тематике, смыслу и стилю и при запросе публикует пост с четырьмя оценками в канале назначения. Индексация и публикация управляются отдельно.

## Первый запуск и обновление

1. Создай `.env` из `.env.example` и заполни `TG_API_ID`, `TG_API_HASH`, `TG_BOT_TOKEN`, `TG_ADMIN_IDS`. При обновлении не меняй существующие значения и том Compose.
2. Пользовательский аккаунт должен иметь право публикации в канале назначения. У канала должна быть группа обсуждений, где бот может писать сообщения.
3. Если пользовательской сессии ещё нет, запусти `docker compose run --rm --build bot login` и введи код Telegram.
4. Запусти `docker compose up -d --build`. Если раньше использовался дополнительный `compose.semantic.yaml`, команда с двумя файлами тоже работает. Локальный каталог `./model` больше не подключается.
5. Модель MiniLM при запуске скачивается в постоянный том `/data/model`, только если там нет проверенных файлов. Контрольные суммы проверяются при загрузке. После первой загрузки образ и файлы можно переносить вместе с томом `data`. Доступность модели видна в `/status`. До включения `/llm on` работает классический анализ.

## Панель в личке бота

Напиши `/start`, чтобы открыть кнопки. Добавление маршрута, свой лимит индексации и ID поста можно вводить по подсказке бота следующим сообщением; `/cancel` отменяет ввод. Команды принимаются только от ID из `TG_ADMIN_IDS` и только в личке. Бот показывает ошибки чтения, отправки и загрузки модели в личке администратора; повторяющиеся ошибки ограничены одним уведомлением за 10 минут. Последние ошибки можно открыть через `/errors`.

| Команда | Действие |
|---|---|
| `/route @source @destination` | Настроить маршрут и показать объём канала. Бот предложит кнопки индексации. |
| `/index @source 500` | Просмотреть следующие 500 сообщений, сохранить тексты и признаки в базу. `all` — вся история; `new` — пропустить старую историю и отслеживать новые посты. |
| `/status` | Модель, число сообщений, прогресс индексации, публикации, очередь, паузы и последние ошибки. |
| `/summary @source 100` | Средние сохранённые оценки первых 100 проиндексированных постов с текстом. Без числа — всей базы. |
| `/analyze @source 123` | Пересчитать оценку конкретного поста в текущем режиме без публикации. Можно вызывать повторно. |
| `/llm on` / `/llm off` | Включить MiniLM или классический анализ. Ранее опубликованные отчёты не меняются; новая команда `/analyze` рассчитывает оценку заново. |
| `/autopost @source on` | Автоматически публиковать **новые** проиндексированные посты. Для нового маршрута выключено. `off` отключает. |
| `/queue`, `/stopqueue @source`, `/startqueue @source` | Просмотр, остановка и возобновление отправки. Индексация при остановке очереди продолжается. |
| `/pause @source`, `/resume @source` | Остановить или возобновить чтение и отправку. |
| `/drain @source` | Остановить чтение, доставить имеющуюся очередь. |
| `/snooze @source 30` | Отложить комментарии на 30 минут; публикация постов продолжается. `0` отменяет ожидание. |

Чтобы опубликовать отдельный пост, перешли его боту из настроенного исходного канала. Бот каждый раз пересчитывает оценку по уже проиндексированной истории этого канала и ставит отдельную публикацию в очередь. Один пост можно переслать повторно, например до и после переключения MiniLM: каждая пересылка создаст новый пост и новый комментарий. Если Telegram скрывает исходный канал пересылки, бот сообщит об этом; для оценки без публикации используй `/analyze`.

Для приватного канала назначения укажи ID вида `-100…`. При смене назначения очередь прежнего канала нужно сначала опустошить через `/drain`; если она больше не нужна, используй `/route @source @new_destination skip_pending`. Сохранённая база анализа остаётся. Старые маршруты продолжают работать с прежним режимом автопубликации после обновления. Новые маршруты начинают с выключенной автопубликацией и с паузы индексации.

## Как устроен анализ

Тексты сравниваются только с более ранними постами **того же** источника. Поиск кандидатов использует слова, фразы, символьные последовательности, тематическую лексику и стиль. MiniLM добавляет эмбеддинги для смысла. При включении MiniLM старые признаки могут дополняться постепенно, а при запросе `/analyze` недостающие в кандидатах эмбеддинги рассчитываются сразу. Первая публикация источника получает 100% по четырём показателям.

Посты без текста учитываются в прогрессе просмотра, но не получают оценок. При запрете пересылки бот пытается создать копию текста, форматирования и доступных вложений. Часть специальных и защищённых медиа Telegram не позволяет воспроизвести. Ограничения Telegram на частоту запросов сохраняются в базе и учитываются после перезапуска.

SQLite, сессии, настройки, очередь и модель находятся в томе Compose `data`. Для локальных проверок установи зависимости из `requirements.txt` и запусти `python -m unittest discover -s tests -v`. Проверка реальной MiniLM требует `requirements-semantic.txt` и `TEST_MODEL_DIR`.
